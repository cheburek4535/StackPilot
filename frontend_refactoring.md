# StackPilot Frontend Refactoring Plan

**ВНИМАНИЕ ДЛЯ АГЕНТА:** Этот документ описывает архитектурный долг фронтенд-части (SvelteKit) проекта StackPilot. Твоя задача — провести рефакторинг UI без изменения поведения приложения, чтобы сделать кодовую базу поддерживаемой и тестируемой.

---

## 1. Ликвидация Frontend "God Object"
**Где:** `src/routes/create/+page.svelte`
**Проблема:** Файл весит почти 200 КБ и содержит более 4300 строк кода. Он нарушает принцип единой ответственности (Single Responsibility Principle). Вся логика мастера создания проектов (управление 6 шагами, валидация стека, работа с Tauri IPC, управление сессией, таймеры опроса, показ модалок и превью) замешана в один гигантский монолитный компонент. 

**План действий (Постепенный рефакторинг):**

### Шаг 1: Изоляция состояния (State Management)
1. Создать файл `src/lib/modules/project_creator/createStore.svelte.ts`.
2. Вынести все глобальные переменные состояния из `+page.svelte` (такие как `tree`, `mode`, `phase`, `selectedType`, `backendLangs`, `selectedFrameworks` и т.д.) в экспортируемый класс или функцию, возвращающую Svelte 5 реактивный контекст (runes `$state`, `$derived`).
3. Использовать `setContext` на уровне корневой страницы и `getContext` внутри дочерних компонентов для доступа к этому состоянию без Prop Drilling.
4. Вынести логику `checkConstructorScroll`, пересчета `stackIssues` и взаимодействия с `createSession.ts` в методы этого стора.

### Шаг 2: Компонентная декомпозиция (UI Split)
1. Разбить огромный шаблон `+page.svelte` на логические секции-компоненты:
   - `WizardConstructor.svelte` (Фазы 0-4)
   - `EnvironmentPanel.svelte` (Фаза 5)
   - `ExecutionPanel.svelte` (Фаза 6)
   - Подкомпоненты для каждого шага: `StepProjectType.svelte`, `StepFrameworks.svelte`, `StepTools.svelte` и т.д.
2. Ленивые импорты (уже частично используемые в коде) сохранить, но подключать их более элегантно через новый стор.
3. Важно: при извлечении компонентов убедитесь, что привязки Svelte (bindings) работают корректно и не теряют реактивности.

## 2. Улучшение работы с памятью при маршрутизации
**Где:** Взаимодействие `+page.svelte` с другими вкладками.
**Проблема:** При переключении вкладок SvelteKit жестко уничтожает (unmounts) компонент страницы. Сейчас состояние мастера сохраняется через `createSession.ts` (в `sessionStorage`).
**Рекомендация:** Убедиться, что при вынесении состояния в `createStore.svelte.ts` логика сохранения (debounce `setTimeout` на 300мс) и восстановления при инициализации перенесена чисто, не вызывает гонок (race conditions) при быстром клике по вкладкам, а все интервалы (`setInterval`) гарантированно зачищаются при размонтировании корневого компонента.
